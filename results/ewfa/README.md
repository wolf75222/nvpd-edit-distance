# eWFA-GPU, IEEE Access 2022

Job 838492 compiled the original unit-cost edit-distance implementation of Aguado-Puig et al. for one ROMEO GH200 with CUDA 13 and `make SM=90 COMPUTE=90 all`. The archive contains a fixed 128-bit traceback representation and a loop over distances strictly below 64. Its two-bit alphabet represents A, C, G and T. Both restrictions apply to this comparison. [2022 paper](https://doi.org/10.1109/ACCESS.2022.3182714) · [Authors’ source, pinned revision](https://github.com/quim0/eWFA-GPU/tree/8b7817cc1623b297aace606aeb0b72dca64d39a8) · [Kernel stop condition](https://github.com/quim0/eWFA-GPU/blob/8b7817cc1623b297aace606aeb0b72dca64d39a8/src/kernels.cu#L259)

Each row is a batch of distinct pairs. Each pair is aligned once per invocation. All three programs reconstruct the optimal path. The 5% prefix with edlib score 66 and the five whole standard 2% pairs fall outside the release's distance range. The benchmark records their oracle distances before omitting them from GPU runs. The additional 0.5% case uses the project's generator, seed 2026, replicates 1–5. The two prefix cases use those same replicate numbers from the standard 5k cohorts, with both strings truncated at offset 1,000. [FASTA hashes, actual lengths and distances](838492/pairs.csv)

The table gives medians over five fresh processes after one discarded process per program/input, with a fixed-seed shuffle of program order. `process_seconds` includes process startup, input reading, allocation, alignment and exit. The GPU context startup and file reading precede the upstream `batch_seconds` timer. That timer includes worker setup, GPU allocations, copies, sequence packing, alignment, GPU CIGAR recovery, copy to host and release, with printing disabled. Both baselines time path production after reading the converted input. The NvPD runner initializes its CUDA context inside that timer and processes pairs serially with one reusable workspace. edlib uses one host thread and returns a per-base path. The upstream GPU processes alignments in one concurrent batch with one host worker. Comparing full process times preserves those startup differences. Four or five pairs give startup-dominated observations and do not establish saturated throughput. [Individual timings](838492/trials.csv) · [Software and hardware](838492/environment.txt)

## Correctness and replay

The original `-p` text formatter prints the character code of the following edit where a match count is required and omits a final pending run. All 14 stock text CIGARs failed replay. In a separate verification build a host-side output patch reads the GPU score and the signed run records after CUDA synchronization. All 14 raw paths consumed both complete strings, matched equal bases at each match, and had edit cost equal to the device and edlib scores. Only the unmodified release provided timing samples. [Original text formatter](https://github.com/quim0/eWFA-GPU/blob/8b7817cc1623b297aace606aeb0b72dca64d39a8/src/wavefront.cuh#L162) · [Validation-only output patch](../../bench/gpu/ewfa/ewfa_validation.patch)

Run `sbatch --account="$ROMEO_PROJECT" --partition=instant bench/gpu/ewfa/ewfa.sbatch` from the checkout. With an offline archive, set `EWFA_ARCHIVE` to the pinned source tarball. The script checks the published archive digest and the project-pinned edlib digest, builds both upstream binaries, regenerates the FASTA data, verifies the alignments and writes CSV results.
